Introduction

Algorithms are the backbone of machine learning: they are the procedures that turn data into models, and models into predictions. Choosing the right algorithm starts with classification — knowing what family an algorithm belongs to, what kind of data it learns from, and what it is used for in the real world. This artifact is a visual framework of twelve widely used algorithms, organized first by learning style (supervised or unsupervised) and tagged by application domain (tabular data, computer vision, natural language processing, and generative AI).

Objective

To identify and categorize key machine learning algorithms accurately, illustrate their types and primary application domains in one visually clear framework, and give practical, real-world examples of each — creating a reference I can reuse whenever a modeling problem requires selecting an approach.

Description

The framework below begins with the big picture — how artificial intelligence, machine learning, and deep learning nest inside one another, and how learning splits into supervised and unsupervised styles. It then presents each algorithm as a card: its learning style, its application domains, a plain-English explanation of how it works, and example applications. A closing section explains the reasoning behind the classification itself.

The Visual Framework

Supervised Learning

Trained on labeled examples; used to predict a category (classification) or a number (regression).

Linear Regression

Supervised · Regression
Tabular Data

How it works: Fits the straight line (or plane) that best maps inputs to a numeric output by minimizing the overall prediction error.

Used for: House-price estimation, sales forecasting, predicting delivery times.

Logistic Regression

Supervised · Classification
Tabular Data

How it works: Passes a linear score through an S-shaped (sigmoid) curve to produce a probability, then classifies by a threshold — despite the name, it is a classifier.

Used for: Customer-churn prediction, loan-default risk, medical screening.

Decision Tree

Supervised · Classification & Regression
Tabular Data

How it works: Asks a sequence of yes/no questions about the features, splitting the data at each step until each leaf holds a prediction. Fully interpretable — every decision can be read aloud.

Used for: Credit approval, fruit sorting, triage rules, eligibility checks.

Random Forest

Supervised · Classification & Regression
Tabular DataComputer Vision

How it works: Builds hundreds of decision trees on random samples of the data and features, then lets them vote (classification) or average (regression), canceling out individual trees' errors.

Used for: Fraud detection, risk scoring, feature-importance analysis, image pixel classification.

Support Vector Machine (SVM)

Supervised · Classification
Tabular DataComputer Vision

How it works: Draws the boundary between classes with the widest possible margin; kernel functions let that boundary curve through higher-dimensional space when classes are not linearly separable.

Used for: Image classification, text categorization, bioinformatics (e.g., gene classification).

K-Nearest Neighbors (KNN)

Supervised · Classification & Regression
Tabular DataComputer Vision

How it works: Stores the training data and classifies a new item by the majority label of its K closest examples — "you are like the neighbors you resemble."

Used for: Recommendation ("similar items"), simple image recognition, anomaly spotting.

Naive Bayes

Supervised · Classification
NLPTabular Data

How it works: Applies Bayes' theorem while (naively) treating each feature as independent evidence for a class; extremely fast and effective for text despite the simplification.

Used for: Spam filtering, sentiment analysis, document categorization.

Unsupervised Learning

Trained on unlabeled data; used to discover groups, structure, and compact representations.

K-Means Clustering

Unsupervised · Clustering
Tabular DataComputer Vision

How it works: Picks K cluster centers, assigns each point to its nearest center, recomputes the centers, and repeats until the groups stop moving.

Used for: Customer segmentation, image compression and segmentation, market basket grouping.

Hierarchical Clustering

Unsupervised · Clustering
Tabular Data

How it works: Repeatedly merges the two closest items or groups, building a tree (dendrogram) of groupings that can be cut at any level of detail.

Used for: Product taxonomies, gene-expression analysis, document organization.

Principal Component Analysis (PCA)

Unsupervised · Dimensionality Reduction
Tabular DataComputer Vision

How it works: Rotates the data onto new axes ordered by how much variation each captures, so a few components can represent many original features with little information loss.

Used for: Visualizing high-dimensional data, compressing features before modeling, noise reduction.

Deep Learning & Generative AI

Neural-network methods that cut across the styles above: they are usually trained supervised or self-supervised, and they power most modern vision, language, and generative systems.

Neural Networks (Deep Learning)

Supervised / Self-supervised
Computer VisionNLPGenerative AITabular Data

How it works: Layers of simple units transform the input step by step; training adjusts millions of connection weights by gradient descent so the network's output matches the target. Depth lets it learn features (edges, then shapes, then objects) automatically.

Used for: Image and speech recognition, translation, image generation, game playing.

Transformers & Large Language Models

Self-supervised · Generative
NLPGenerative AI

How it works: Text is split into tokens; a mechanism called attention lets every token weigh the relevance of the others, and the model is trained to predict the next token. Repeated prediction, at very large scale, produces fluent generation, summarization, and question answering.

Used for: Chatbots and assistants (e.g., ChatGPT), code generation, summarization, drafting and translation.

How I Classified Them — And Why

I classified on two axes, in a deliberate order. The primary axis is learning style — supervised versus unsupervised — because it answers the first question of any real project: do I have labeled examples of the outcome I want? If yes, supervised methods apply; if no, the task is to discover structure, and unsupervised methods apply. This single distinction decides feasibility before accuracy is even discussed, so it forms the framework's main branches.

The secondary axis is application domain — tabular data, computer vision, NLP, and generative AI — shown as color tags rather than branches, because most algorithms serve more than one domain (a random forest can score credit risk from a spreadsheet or classify pixels in an image). Tags preserve that many-to-many relationship instead of forcing each algorithm into a single box.

Two judgment calls are worth explaining. First, deep learning gets its own band rather than a branch: neural networks are a model family, not a learning style — they are trained supervised for recognition, self-supervised for language models, and they now dominate the generative-AI domain the course emphasizes. Placing them under only one style would misstate how they are actually used. Second, within supervised learning I note each algorithm's task (classification, regression, or both), because "predict a category or predict a number" is the next decision a practitioner makes after choosing the supervised branch.

Process

  • Reviewed the Workshop One resources on AI/ML/DL differences, machine learning algorithm families, NLP, and computer vision.
  • Selected twelve algorithms that span both learning styles and all four application domains, prioritizing the algorithms named in the course materials.
  • For each algorithm, verified its learning style, primary task, and representative real-world uses against the course resources.
  • Designed the framework as a hand-built web page: a hierarchy diagram, color-coded domain tags, and uniform cards so any two algorithms can be compared at a glance.
  • Wrote the classification rationale and reflection, and reviewed the page for accuracy, consistency, and readability on mobile and desktop.

Tools and Technologies Used

Hand-written HTML5, CSS, and inline SVG (no frameworks), published with GitHub Pages. Content sources: the Workshop One course resources, including Microsoft's machine learning algorithms overview, AWS's "What is Machine Learning?", and the articles on AI/ML/DL/GenAI differences listed in the references.

Relevance

Model selection is the highest-leverage decision in a machine learning project: the wrong family wastes weeks, while the right one makes the rest of the pipeline simpler. This framework is the checklist I will run through at the start of future projects — labels first, domain second, interpretability and data size as tie-breakers — and it anchors the more advanced model-development work in the rest of this course and in my engineering practice.

Reflection on Learning

Building this framework taught me that classification is itself a modeling decision. I began expecting a tidy tree — every algorithm in exactly one box — and discovered the interesting cases are the ones that refuse: deep learning spans styles, and most algorithms span domains. Representing that honestly (branches for the decisive distinction, tags for the many-to-many one) was the main design challenge, and solving it clarified the material more than memorizing definitions would have. I also saw my own Workshop One decision-tree assignment differently afterward: the tree I wrote for fruit sorting is one card in this framework, and I can now articulate exactly why it sits where it does — supervised, interpretable, tabular-style features — and when I would reach for a different card instead.
